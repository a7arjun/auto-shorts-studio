# Renew this channel's YouTube authorization

Use the existing Google Cloud project and OAuth client used by `YT_HI_CLIENT_ID`. This reconnects the former Bollywood channel for the English Pokemon pipeline. Do not use the retired Bollywood test workflow.

1. Open https://console.cloud.google.com/auth/audience and select the existing project. Check the publishing status. External **Testing** grants for YouTube scopes expire after seven days. For durable personal operation, use **In production** before generating the replacement token. If Google presents verification requirements, follow them; changing status is not the same as completing verification and does not guarantee a non-expiring token. Do not delete the project or create another channel.
2. Open https://console.cloud.google.com/auth/clients and select the existing **Web application** client. Ensure its authorized redirect URIs include exactly `https://developers.google.com/oauthplayground` (no trailing slash). Save if you add it. Keep client credentials in the provider UI and secret store.
3. Open https://developers.google.com/oauthplayground/ . Gear/settings: enable **Use your own OAuth credentials** and enter the matching client ID and secret. Keep **Access type: Offline**, **Force prompt: Consent Screen**, Google endpoints and server-side flow. Using Playground's default client instead can cause automatic token revocation after 24 hours.
4. In Step 1's scope input, enter `https://www.googleapis.com/auth/youtube.force-ssl` and click **Authorize APIs**. Sign into the Google account that owns the existing channel. If Google presents a channel/Brand Account choice, choose the former Bollywood channel being converted to Pokemon. Review and grant the requested access. Complete account verification directly with Google. If Google blocks authorization, resolve the displayed project/verification configuration rather than repeatedly generating tokens.
5. In Step 2 click **Exchange authorization code for tokens**. Copy the **Refresh token**, not the access token. Do not paste tokens, the client secret, screenshots containing them, or authorization callback URLs into chat.
6. Open https://github.com/a7arjun/auto-shorts-studio/settings/secrets/actions . Edit the repository secret `YT_HI_REFRESH_TOKEN`, paste the new value and save. Keep `YT_HI_CLIENT_ID` and `YT_HI_CLIENT_SECRET` unchanged when reusing the same client. If you changed the client or rotated its secret, update those matching secrets as well. Never save these values as public repository variables or commit them.
7. Open https://github.com/a7arjun/auto-shorts-studio/actions/workflows/pokemon-shorts.yml . **Run workflow → main → mode: probe → Run workflow**. It refreshes the token, checks granted scopes and confirms ownership of the channel associated with reference video `1uvpsNPF63A`; it does not upload. A successful run must show the correct destination and `can_manage: true`. A later **pilot** operation creates one private rendered integration upload, including recent metadata research. Production remains gated until that private pilot and the separate runner are ready.

Sources: [Google OAuth refresh-token expiration](https://developers.google.com/identity/protocols/oauth2#expiration), [OAuth Playground](https://developers.google.com/oauthplayground/), [Sensitive-scope verification](https://developers.google.com/identity/protocols/oauth2/production-readiness/sensitive-scope-verification).
